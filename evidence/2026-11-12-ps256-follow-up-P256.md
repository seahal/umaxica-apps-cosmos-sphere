## Implementation

First-party JWT code in this repository now uses PS256 and RSA keys with at least 3072 bits. ES384,
RS256, PS384, `none`, HMAC and mismatched algorithm headers are rejected. The verifier continues to
check the existing type, issuer, audience, time, nonce, JTI, cache/refetch and fail-closed rules.

The implementation changes the shared JWK and private-key parsing contract, JWT keyring signing,
issuer registry metadata, and the local development/test key installer. The installer stores PKCS#8
RSA private DER and has a key-format marker that discards its previous throwaway local ES384 keyset
before regenerating it. Its local key store contains 21 RSA private keys with moduli at least 3072
bits; the metadata check did not print key material. Production keys were not generated or changed.

Updated token families include OP access, ID and logout verification; RP client assertions; OIDC
state; Jump RT issuance and return verification; and the shared first-party JWT keyring. Tests and
current security/runbook/ADR summaries were updated. The OIDC discovery-profile, RFC 9068,
Preference, RP state, Jump and Cosmos signing records now identify PS256 as current and mark older
ES384 statements as superseded history. ChainSeal and DPoP algorithms were left unchanged.

Private key configuration names whose values must be RSA 3072-or-larger PKCS#8 are:

- `AUTH_JWT_PRIVATE_KEYSET`
- `PREFERENCE_APP_JWT_PRIVATE_KEYSET`
- `PREFERENCE_ORG_JWT_PRIVATE_KEYSET`
- `JWT_<NAMESPACE>_PRIVATE_KEY` for the registry namespaces `AUTH_APP`, `AUTH_ORG`, `ACME_APP`,
  `ACME_ORG`, `CORE_APP`, `CORE_ORG`, `WARP_APP`, `WARP_ORG`, `PALM_APP`, `BASE_APP`, `BASE_ORG`,
  `VISA_APP` and `VISA_ORG`
- `OIDC_CLIENT_<NAMESPACE>_PRIVATE_KEY` for `CORE_APP_JP`, `CORE_ORG_JP`, `WARP_APP_JP`,
  `WARP_ORG_JP` and `PALM_APP_JP`

For `*_PRIVATE_KEYSET`, the value is a JSON object with per-`kid` base64-encoded PKCS#8 DER keys.
Scalar `*_PRIVATE_KEY` values accept PKCS#8 PEM or base64-encoded PKCS#8 DER. Provision only names
owned by each runtime role. No values or secrets are recorded here.
